# FIDESlib coverage baseline

Metrics produced by the local coverage pipeline (`scripts/run_coverage.sh` /
`scripts/run_coverage_sharded.sh`) — see the [README **Coverage** section](README.md#coverage).
Report: `coverage/index.html` (browse locally), machine-readable: `coverage/coverage.xml`.

## What is measured

- **Only `src/` and `api/`** are measured (see `scripts/coverage.gcovr.cfg`); tests,
  benchmarks, examples, `deps`, `nvtx` and build trees are excluded.
- **Host-side code only.** gcov instruments the host pass of `.cpp`/`.cu` files;
  CUDA device code (`__device__`/`__global__` bodies) is not instrumented, so
  kernel-heavy files report lower numbers than "real" coverage. Kernel
  *reachability* is covered separately by the static
  [`KERNEL_USAGE.md`](KERNEL_USAGE.md) report.
- Hot loops wrap gcov's 32-bit hit counters (gcc bug 68080); those lines are
  counted as covered (`suspicious_hits.warn`).
- Benchmark and timing suites are excluded (`P2PBenchmark`, `APIbench`,
  `LLMTests`, `Microbench`), as are `DISABLED_` gtest cases.

## Baseline: full test suite (minus the exclusions above)

Hardware for this baseline: RTX 4060 Ti 16 GB, `FIDESLIB_ARCH=89-real`, Debug
coverage build (`--coverage`, no `-G`), OpenFHE at `/usr/local`.

accumulates gcov counters across all of them):

## Kernel usage (static + runtime cross-check)

gcov cannot see `__global__` bodies, so device code reports as "uncovered"
regardless of reachability. [`KERNEL_USAGE.md`](KERNEL_USAGE.md) (regenerated by
[`scripts/kernel_usage.py`](scripts/kernel_usage.py), wired into both coverage
scripts) classifies all **76** `__global__` kernels under `src/` + `api/` by
static reachability **and** by whether their call sites actually execute in the
coverage run:

- **28 exercised** — at least one library launch site has `hits > 0`.
- **34 referenced but never executed** — the kernel has launch sites, but every
  call-site line is uncovered (or compiled out as unreachable). Concentrated in
  the batched (`LimbPartitionBatch.cu`) and multi-GPU (`LimbPartitionMGPU.cu`)
  paths plus standalone kernels such as `automorph_`, `addMult_`, `square_`,
  `addScaleB_`/`addScaleC_`, and the `*_reuse_b___` family.
- **9 never referenced anywhere** (dead code): `DecompAndModUpConv_spec`,
  `SwitchModulus` (the `__global__` overload), `add___`,
  `binomialDotProdSpecialBatched___`, `conv1_`, `copy1D_`, `dummy`,
  `printConstants`, `test_kernel`.
- **5 referenced only from tests/benchmarks/examples** (library-dead):
  `Bit_Reverse`, `INTT_1D`, `NTT_1D`, `dummy_kernel`, `scalar_mult_`.

This is how to tell whether a kernel is actually reachable despite gcov not
instrumenting device code — e.g. `addScaleB_`'s only launch site
(`LimbPartition.cu:2364`) has 0 hits, so the kernel is compiled, linked and
launchable but never runs in the measured suite.

## Notes on the numbers

- `api/` sits at ~97 %: the OpenFHE-facing API (CryptoContext, serialize,
  plaintext/ciphertext wrappers) is heavily exercised by the interface and
  compat suites. The compat suite was extended to 61 cases walking the previously
  untouched host-side entry points (parameter setters/getters, ciphertext/
  plaintext accessors and operators, symmetric-key Encrypt, eval-key
  serialization, the `fideslib::Serial` context/key round-trips, the start-offset
  accumulate, the convolution transforms, the null-context / unsupported-SerType
  error paths, and direct unit coverage of the two-operand `Ciphertext` add/sub/
  mult primitives). The residual `api/` lines are defensive `OPENFHE_THROW`
  guards ("already loaded" / "must be called before LoadContext").
- The low `src/` function coverage (~22 %) reflects many non-inline helpers in
  `CudaUtils`/`Math`/`NTThelper` that the tests only reach indirectly, plus
  host-side scaffolding around uninstrumented kernels. Note that `.cu` files are
  instrumented for the **host pass only** — device bodies (`__device__`/
  `__global__`) never contribute, so kernel-heavy files are not directly
  comparable to pure-host ones.
- `Limb`, `LimbPartition` and the pool code are in `src/CKKS/` — still the largest
  unexplored area along with bootstrap/approx-mod paths that the compat suite
  exercises only partially.
- The mutable arithmetic entry points (`Eval*Mutable*`) are now wired to the
  FIDESlib `*Mutable` GPU primitives and OpenFHE's mutable ops, so both libraries
  adjust operands in place and skip the operand copy the immutable forms pay on
  adjustment. This also gives the previously-dead `addMutable`/`subMutable`/
  `multMutable`/`addPtMutable`/`subPtMutable`/`multPtMutable` real call sites.
- Guardrails hardened while measuring: `ContextData::GetBootPrecomputation` and
  `GetSecretSwitchingKey`, the `RawCiphertext` missing-key lookups, and the
  remaining `Ciphertext` adjust-failure paths now `throw` instead of `assert` /
  `exit(-1)` / returning an empty key (which silently default-constructed or
  crashed in release builds).

## Pipeline details

- `scripts/run_coverage.sh` — monolithic run (good for quick/small subsets via
  `TEST_FILTER`).
- `scripts/run_coverage_sharded.sh` — one-case-per-process run, crash-isolated,
  resumable (done-file in `coverage/.stats/`), used for the full-suite baseline.
  Each case is a foreground child process; gcda accumulates across exits.
- History: `056503b` fixes a Debug-only `Limb` assert; `d348f33` unblocks the
  pipeline (`-G` removal, `suspicious_hits.warn`, `TEST_FILTER`); `97b1a2c` +
  `1f93d6c` + `d8709e5` add the sharded driver (CASE_FILE mode, resumable
  done-file, foreground execution).
